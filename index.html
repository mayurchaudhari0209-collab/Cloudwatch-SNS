05 · TAKE IT TO AWS

From simulation to real commands.

Examples for your own AWS environment. Replace every placeholder before running.

1. List CloudWatch alarms

See alarms configured in a region.

aws cloudwatch describe-alarms --region YOUR_AWS_REGION
2. List available metrics

Find EC2 CPU utilization metrics.

aws cloudwatch list-metrics --namespace AWS/EC2 --metric-name CPUUtilization --region YOUR_AWS_REGION
3. Create an SNS topic

Creates a topic and returns its ARN.

aws sns create-topic --name RaviShopAlerts --region YOUR_AWS_REGION
4. Subscribe an email

Ravi must confirm the subscription from the email he receives.

aws sns subscribe --topic-arn YOUR_SNS_TOPIC_ARN --protocol email --notification-endpoint YOUR_EMAIL_ADDRESS --region YOUR_AWS_REGION
5. Publish a test message

Tests the topic after subscription confirmation.

aws sns publish --topic-arn YOUR_SNS_TOPIC_ARN --subject "Ravi Shop test alert" --message "This is a test notification." --region YOUR_AWS_REGION
6. Create a CPU alarm

Uses a 5-minute period and two evaluation periods above 80%.

aws cloudwatch put-metric-alarm --alarm-name RaviShop-HighCPU --namespace AWS/EC2 --metric-name CPUUtilization --dimensions Name=InstanceId,Value=YOUR_EC2_INSTANCE_ID --statistic Average --period 300 --evaluation-periods 2 --datapoints-to-alarm 2 --threshold 80 --comparison-operator GreaterThanThreshold --alarm-actions YOUR_SNS_TOPIC_ARN --ok-actions YOUR_SNS_TOPIC_ARN --region YOUR_AWS_REGION
Before you run these: Configure AWS CLI credentials securely and choose the correct region. Your IAM identity needs suitable CloudWatch and SNS permissions; creating or updating the alarm may also require permission for CloudWatch to publish to the SNS topic. Do not paste credentials into this page. EC2 basic monitoring intervals and detailed monitoring differ, so alarm periods should match your monitoring needs.
